Протоколы подключения памяти:

+ SPI (Serial Peripheral Interface) - наиболее распространенный интерфейс для работы с внешней флэш-памятью и EEPROM. Он поддерживает высокую скорость передачи данных и прост в реализации;
+ I2C (Inter-Integrated Circuit) - используется для подключения EEPROM, а также некоторых типов энергонезависимой памяти. Отличается простотой схемотехники и возможностью подключения нескольких устройств на одну шину;
+ QSPI (Quad SPI) - усовершенствованный вариант SPI, позволяющий передавать данные по четырем линиям, что значительно увеличивает скорость работы с флэш-памятью;
+ SDRAM (Synchronous Dynamic RAM) - применяется в более мощных микроконтроллерах, если встроенной RAM недостаточно. Подключение SDRAM требует специализированного контроллера, работающего через 16- или 32-битный интерфейс.

Внешнее взаимодействие:

+ GPIO (General-Purpose Input/Output) - универсальные входы-выходы, позволяющие взаимодействовать с датчиками, светодиодами, кнопками и другими элементами.
+ SPI (Serial Peripheral Interface) — синхронный последовательный интерфейс, часто используемый для связи микроконтроллера с периферийными устройствами, такими как датчики, дисплеи и карты памяти. Работает по принципу «ведущий-ведомый» (Master-Slave) и использует несколько линий связи: MOSI (Master Out Slave In), MISO (Master In Slave Out), SCK (Serial Clock) и CS (Chip Select).
+ I2C (Inter-Integrated Circuit) — еще один последовательный интерфейс, но в отличие от SPI, использует всего две линии связи: SDA (Serial Data) и SCL (Serial Clock). Он позволяет подключать несколько устройств к одной шине, что делает его удобным для работы с датчиками и небольшими периферийными модулями.
+ UART (Universal Asynchronous Receiver-Transmitter) - асинхронный последовательный интерфейс, предназначенный для обмена данными между микроконтроллерами или с компьютером. Он работает без тактового сигнала, используя старт- и стоп-биты для синхронизации передачи.
+ CAN (Controller Area Network) - шина передачи данных, широко используемая в автомобилях и промышленности. Позволяет устройствам обмениваться сообщениями без центрального узла, используя механизм приоритета сообщений.
+ LIN (Local Interconnect Network) - более простая и дешевая альтернатива CAN, применяемая в автомобильной электронике для управления второстепенными системами (например, стеклоподъемниками, освещением).
+ USB (Universal Serial Bus) - универсальный интерфейс для подключения микроконтроллеров к компьютерам и периферийным устройствам. Поддерживает разные режимы передачи данных и позволяет заряжать устройства.
+ Ethernet - проводной интерфейс для передачи данных в сети, используемый в промышленных системах и умных устройствах.
+ Wi-Fi, Bluetooth - беспроводные интерфейсы связи, применяемые в IoT-устройствах и потребительской электронике


Отладочные порты:

Многие микроконтроллеры имеют встроенные отладочные интерфейсы, через которые можно не только отлаживать прошивку, но и извлекать её. Наиболее распространённые из них - это:

- JTAG (Joint Test Action Group) - один из старейших и самых гибких отладочных интерфейсов. Он позволяет пошагово выполнять код, считывать и записывать регистры и память, управлять тактированием. Требует минимум 4 линии: TCK (тактовый), TMS (состояние), TDI (данные на вход), TDO (данные на выход);
- SWD (Serial Wire Debug) - более компактная альтернатива JTAG, используемая в ARM Cortex-M-микроконтроллерах. Всего две линии: SWDIO (двунаправленные данные) и SWCLK (тактовая). Несмотря на простоту, сохраняет большинство возможностей JTAG;
- cJTAG (Compact JTAG) - урезанный вариант JTAG, передающий данные по одной линии. Используется в новых микросхемах, где минимизация количества выводов критична;
- ICSP (In-Circuit Serial Programming) - применяется в микроконтроллерах PIC. Позволяет программировать и считывать память прямо в устройстве;
- UART - у некоторых микроконтроллеров предусмотрен режим загрузки через UART, который может использоваться для чтения памяти при наличии соответствующих команд.

| JTAG      | Отладка, программирование       | 4–5          | Да              | ARM, MIPS, другие     |
| SWD       | Отладка, программирование       | 2            | Да              | ARM Cortex-M          |
| cJTAG     | Компактный отладочный интерфейс | 1            | Да              | Современные SoC       |
| ICSP      | Программирование                | 5–6          | Да              | PIC                   |
| UART Boot | Загрузка и отладка              | 2–3          | Иногда          | STM32, ESP, др.       |

Схемы подключения

JTAG:
- TCK → тактовый вход JTAG-интерфейса микроконтроллера;
- TMS → выбор состояния;
- TDI → данные от программатора к микроконтроллеру;
- TDO → данные от микроконтроллера к программатору;
- GND → общая земля.

SWD:
- SWDIO → данные (двунаправленный канал);
- SWCLK → тактовая линия;
- GND → общая земля.

UART (TTL):
- TX программатора → RX микроконтроллера;
- RX программатора → TX микроконтроллера;
- GND → общая земля.

ICSP (для PIC):
- Vpp/MCLR → линия сброса/программирования;
- Vdd → питание;
- GND → земля;
- PGD → данные;
- PGC → тактирование.

UART Boot (например, STM32):
- BOOT0/BOOT1 → пины режима загрузки;
- UART TX/RX → соединение с компьютером или адаптером;
- GND → земля.


* Алгоритм

+ Определить тип микроконтроллера и внешних чипов памяти.
+ Найти доступные интерфейсы (JTAG, UART, SPI и т.д.).
+ Проверить наличие защиты (например, read-out protection), т.е. доступность методов.
+ Выбрать метод (аппаратный или программный).
+ Настроить оборудование и инструменты.
+ Извлечь прошивку.
+ Верифицировать и сохранить образ.
